# 离线 TOTP

`Totp.cpp` 实现 RFC 4226 HOTP 与 RFC 6238 TOTP，设备端不联网、不向任何时间服务查询，也不
在日志中输出密钥。认证后的串口 CLI 可直接生成验证码：

```
totp time 1760000000          # 由可信主机写入 Unix 秒；掉电后需要重新写入
totp time                     # 查看当前设备时间
totp JBSWY3DPEHPK3PXP         # 默认 6 位、30 秒、SHA-1
totp JBSWY3DPEHPK3PXP 8 30 sha256
totp clear                    # 清除时钟锚点
```

`OK code=123456 remaining=17` 中的 `remaining` 是当前周期剩余秒数。`totp time` 只在认证
会话内可用；命令不会回显 base32 密钥，密钥缓冲区在解析后立即清零。

## 时间策略

- 设备没有可信的电池 RTC 驱动。时钟由 `totp_clock_set_unix(unix, millis())` 锚定，之后
  用 `millis()` 单调递增计算，避免每次代码生成都重新读墙钟。
- `millis()` 是 32 位回绕计数；回绕本身不会让时钟倒退。若调用方传入更早的 `millis()`，
  时钟被标记为无效，而不是返回一个错误但看起来正常的 TOTP。
- 掉电或固件重启后时钟无效，必须由可信主机重新写入。不要把手机时间当作未经认证的输入：
  该命令只在已解锁的 CLI 会话中执行。
- 若硬件安装 RTC（例如 PCF85063/DS3231），应只把 RTC 读数作为 `totp time` 的来源；不要
  在代码里编造 RTC 型号或 I2C 地址。

## 算法与边界

- 算法：SHA-1 / SHA-256 / SHA-512；位数 6–8；周期 1–300 秒（默认 30）。
- Base32 严格解码：只接受 A-Z/2-7、可选空格和尾部 `=`；非法字符、非零尾位和超过 64 字节
  的密钥被拒绝。
- HMAC 使用本地 SHA-1 实现和已有的 HMAC-SHA256/SHA512；动态截断按 RFC 4226 的
  31 位掩码与 `10^digits` 取模。
- 自检覆盖 RFC 6238 的 18 个 SHA-1/256/512 向量、RFC 2202 HMAC-SHA1 向量和 RFC 4648
  Base32 向量；Python 测试用 `hashlib`/`hmac` 独立计算同一组值并与 C++ 探针比较。
