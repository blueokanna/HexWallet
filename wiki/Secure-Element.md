# Secure element (SE051C2HQ1)

[中文](Secure-Element-zh) · [Home](Home)

Status: implemented up to an authenticated channel and applet commands, host-tested against a mock
transport, **not validated on a real card, and not a signing backend**. The wallet still derives and
signs in MCU RAM, so the custody gate stays closed and device builds refuse to hold a wallet.

## What exists

| Piece | File | State |
| --- | --- | --- |
| Arduino I²C port for NXP Plug & Trust (`axI2CInit/Read/Write/Term`, timing) | `Se051ArduinoPort.cpp` | written against the pinned NXP commit `7102413e0457d3dfa4fc4be686ca8ec50bd9f5e2` |
| SCP03 channel: AES-CMAC KDF, card/host cryptograms, C-MAC wrapping, R-MAC check, counter advance | `Se051Scp03.cpp` | host-verified against an independent Python AES-128/CMAC implementation; five rejection paths tested |
| APDU encoding (CLA/INS/P1/P2, TLV, curve ids) | `Se051Apdu.cpp` | every frame pinned byte for byte, e.g. `CreateECCurve(secp256k1)` = `80 01 0B 04 03 41 01 10` |
| Curve provisioning (CreateECCurve + five SetECCurveParam) | `Se051Curves.cpp`, `Se051Provisioning.cpp` | parameters recomputed from `src/EcdsaCurve.h` and compared byte for byte |
| PIN session (CreateSession, policy, VerifySessionUserID, `0x63Cx` attempts) | `Se051Apdu.cpp`, `Se051PinSession` | host-tested state machine; unauthenticated sessions refuse HMAC locally |
| Custody gate | `WalletCustody.cpp` | five independent facts, each with its own blocker text |

Constants worth knowing: the applet AID is
`A0 00 00 03 96 54 53 00 00 00 01 03 00 00 00 00`; curve ids are `NIST_P256=0x03`,
`Secp256k1=0x10`, `ECC_ED_25519=0x40`, `ECC_MONT_DH_25519=0x41`; a curve id travels in TLV tag
`0x41`, not in P1/P2.

## Custody gate

`secure_custody_backend_ready()` is not a constant. It is the conjunction of:

| Fact | Source | Who can make it true |
| --- | --- | --- |
| `backend_registered` | `secure_element_name()` | a linked backend registers itself |
| `channel_authenticated` | `secure_element_ready()` | successful SCP03 handshake |
| `user_authenticated` | `secure_element_user_authenticated()` | in-card PIN session |
| `keys_non_exportable` | `secure_element_keys_non_exportable()` | backend promises keys never leave the card |
| `wallet_uses_handles` | query registered by `WalletSession` | derivation and signing actually go through handles |

`custody_gate_blocker()` returns the first fact that is false, and `custody <coin>` prints it. The
self-test falsifies each fact in turn and checks that the reported blocker moves to the right one,
including when two facts are false at once. No single `return true` opens the gate.

SCP03 authenticates the **host**; the PIN authenticates the **person**. Keeping them separate is
the point: "the cable is connected" is not "the owner is present".

## What is missing

| Gap | Why it blocks custody |
| --- | --- |
| Real-card interop | These bytes match the public SDK, which is not the same as a SE051C2 accepting them; status words beyond `0x9000`, policy semantics and per-part curve authorisation are in an unpublished spec |
| Session resumption | A real card returns a session id in `CreateSession`; whether that session survives a failed PIN depends on applet policy, so nothing is guessed |
| PIN derivation | PBKDF2 / PIN encryption into the card is not implemented |
| In-card BIP32 | Needs HMAC-SHA512 **plus** `(I_L + k_par) mod n`, invalid-child checks and non-exportable object creation; a single HMAC APDU is not BIP32 |
| Handle-based wallet | Derivation, review and signing must stop taking a plaintext seed or private key |
| Device-unique keys | Host key protection and device provisioning are not in the tree |

## Deliberate refusals

- A curve that was created but not fully parameterised is reported as **Absent**, not as usable. A
  half-written curve that signs bytes the firmware cannot verify is the worst possible failure.
- `0x6A80`/`0x6A88` mean "curve not installed" only during the one allowed install-then-retry path;
  every other status word is an error.
- The driver never invents curve analogue parameters for a four-colour panel or a partial-refresh
  waveform, and it never guesses SE pins.
- No plaintext fallback: if custody is required and unavailable, wallet operations fail with
  `CustodyUnavailable` instead of degrading.

## Reproduce

```powershell
git clone https://github.com/NXP/plug-and-trust build/nxp-plug-and-trust
git -C build/nxp-plug-and-trust checkout 7102413e0457d3dfa4fc4be686ca8ec50bd9f5e2
powershell -ExecutionPolicy Bypass -File tests/host/se051_port_check.ps1
powershell -ExecutionPolicy Bypass -File tests/host/se051_port_check.ps1 -Device
```

The SCP03 vectors are generated by an independent Python implementation that first proves itself
against FIPS-197 C.1 and RFC 4493. Tampered, truncated, oversized, session-less and short-buffer
responses must all be rejected.

The full engineering record, including the EasyEDA review hash, is `wiki/se051-integration.md`.
