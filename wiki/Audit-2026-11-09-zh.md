## 已修复的问题

| 位置 | 问题与触发条件 | 修复与验证 |
| --- | --- | --- |
| `AlephiumTransaction.cpp` | 合法紧凑整数解码执行 `out + 33 - width`，先产生超出 32 字节数组的指针。完整链测试被 UBSan 中止。 | 先计算偏移，且不对零长度尾部做复制；增加 1、2、4 字节编码回归。SDK 交易向量在 ASan/UBSan 下通过。 |
| `AeternityTransaction.cpp` | 自检的畸形交易缓冲区只容纳 75 字节正文，漏算 2 字节 RLP 列表头；ASan 检出栈越界写。这是自检路径缺陷，不宣称已证明远程攻击。 | 独立计算正文与封装容量，改用有容量检查的列表封装函数；同时补强本地 RLP 追加函数的参数和剩余容量检查。 |
| `ChainCommon.cpp/.h` | RLP 和十六进制长度计算可在极端 `size_t` 输入上回绕；空输出指针没有让 writer 失效。 | 使用剩余容量比较，编码总长度溢出返回失败；避免空指针算术，失败时清除列表输出长度。覆盖 `SIZE_MAX`、精确容量和差一字节容量。现有上层通常限制了输入长度，未把此问题描述为已证实的远程可利用漏洞。 |
| `base58.cpp` | `strchr` 会把嵌入的 NUL 匹配到字母表结束符，解码器把它当成第 58 个数字。 | 明确拒绝 NUL；补上编码工作区乘法溢出检查，失败路径也擦除解码工作区。覆盖嵌入 NUL 和 0–128 字节往返编码。 |
| `EvmTransaction.cpp/.h` | 自定义 Token 的合成 profile 指向可变注册表。仅比较 profile 指针无法证明签名时的名称、符号和精度仍与原审阅一致。 | 审阅时保存 Token 元数据摘要，签名前重解析并比较。测试覆盖同一合约、同一表项、同一精度，仅修改标签的情况：旧请求拒绝并清空签名输出，新审阅可以正常签名。这是签名 API 的防御补强；CLI 还有独立的待审阅命令限制。 |
| `EvmTransaction.cpp` | 审阅格式化未检查金额和 NFT ID 文本是否在数组内结束；短输出缓冲区可能留下截断文字。 | 格式化前验证结束符，失败时清空可见文本；回归验证异常文本和短缓冲区。 |
| `WalletCli.cpp`、`WalletCliPolicy.cpp/.h` | 精度使用不检查结束位置的 `strtoul`，`6junk` 会当作 6，非数字可能当作 0。 | 使用共享的严格十进制解析器，限定精度范围，地址索引复用同一解析规则。覆盖符号、空白、尾随垃圾、整数上限和溢出。 |
| `WalletCustody.cpp` | Starknet 分支缺少 `break`，具体托管阻塞原因被覆盖为“未知密钥方案”。 | 补上分支终止并检查返回原因；不改变实际托管能力。 |
| `tools/token_audit.ps1` | 未核验条目、没有匹配条目时可能返回成功；缺少 RPC 网络核对，NFT 检查接受“所有接口都返回真”的合约。 | 校验 JSON-RPC 响应、固件 chain ID、合约代码、ABI 元数据和 ERC-165 正反例；部分未完成返回 2，不匹配返回 1，无匹配直接失败。增加 10 组离线故障注入测试并接入 CI。 |
| `tools/token_audit.ps1` | Monad、Plasma、Berachain 的原 PublicNode 地址返回 404；Kava 映射键与固件不一致。 | 更新端点并修正 `kavaevm` 键；重新完成全表查询。 |

## Token 与 NFT 在线核验

核验日期为 2026-11-09，使用公开节点，只读查询，没有广播交易。

- EVM 全表 76 项完成：74 个同质化 Token 和 2 个 NFT 合约；精度/接口不匹配 0，无法访问 0，跳过 0。
- 2 项标签差异为 Polygon 和 Optimism 的桥接 USDC：固件使用 `USDC.e` 区分桥接资产，合约返回 `USDC`，两者精度都是 6。保留这个区分，没有为了让日志全绿而改成容易混淆的标签。
- TRON USDT 合约返回 `Tether USD`、`USDT`、6 位精度。TRC-10 `1002000` 返回 BitTorrent/BTT、6；`1003000` 返回 JUST/JST、6；`1000001` 返回 SEED，响应省略零值 precision 字段。原始响应单独保存。

这些结果证明注册信息与当时节点响应的一致性，不证明合约安全、发行方真实性、资产流动性、每个 NFT 的所有权、任意调用语义或未来可用性。不能把 ABI 识别能力直接算作所有 Token/NFT 的生产签名支持。

NFT 正反例依据 [ERC-165](https://eips.ethereum.org/EIPS/eip-165)。网络与只读查询参数参考 [Ethereum JSON-RPC](https://ethereum.org/developers/docs/apis/json-rpc/)、[Monad 主网配置](https://docs.monad.xyz/developer-essentials/network-information)、[Berachain 网络配置](https://docs.berachain.com/build/getting-started/common-resources)、[Plasma 网络注册](https://chainid.network/chain/9745/)及 [TRON 只读调用说明](https://developers.tron.network/reference/triggerconstantcontract)。

## 尚未解决的生产阻塞

1. **安全芯片托管没有接通钱包层。** `WalletSession.cpp` 在非 host-test 构建中固定返回 `CustodyUnavailable`；`WalletCustody.cpp` 的 active profile 仍是软件 profile。SCP03/APDU 传输能力不等于密钥派生和签名已经通过不可导出的句柄完成。需要真实硬件、明确的派生/恢复方案及按密钥算法验证的实现，不能通过把 ready 改为 true 或放开 MCU 种子路径解决。
2. **没有本次实机与节点验收。** 完整构建已通过，但还需要在实际板型配置上验证显示确认、断电恢复、持久化故障、签名后节点验签/接受。P4 本次完整构建采用默认无屏配置，不代表 P4 电子纸及所有其他板型均完成验收。
3. **启动保护仍需要部署配置。** `HEXWALLET_REQUIRE_VERIFIED_BOOT` 默认仍为 0。发布设备必须明确安全启动、Flash 加密、固件更新和恢复策略，并验证相应硬件状态。本次没有写入 eFuse。
4. **性能与物理攻击结论未建立。** 主机向量和单帧栈预算通过不能证明 MCU 延迟、运行时峰值堆栈、长期稳定性、故障注入或侧信道安全。本次没有声称实现了“绝对稳定”或“极致性能”。

完整设备构建命令：

```powershell
foreach ($target in @('esp32s3', 'esp32p4')) {
  & build/audit-arduino/bin/arduino-cli.exe compile `
    --config-file build/audit-arduino/arduino-cli.yaml `
    --fqbn "esp32:esp32:$target" --jobs 4 `
    --library build/audit-arduino/libraries/lvgl `
    --build-path "build/audit-device-$target" `
    --build-property compiler.cpp.extra_flags=-DLV_CONF_INCLUDE_SIMPLE `
    --build-property compiler.c.extra_flags=-DLV_CONF_INCLUDE_SIMPLE .
  if ($LASTEXITCODE -ne 0) { throw "$target build failed" }
}
```

本次本地构建分别保存在 `build/audit-native`、`build/audit-sanitized`、`build/audit-host`、`build/audit-auth`、`build/audit-dcc` 和 `build/audit-device-*`。日志在 `build/audit-logs`，其中 `sanitizer-suite.log`、`host-exact-sdk.log`、`device-esp32s3.log`、`device-esp32p4.log`、`stack-esp32*.log`、`token-live-final.log`、`tron-live.json` 是最终主要证据；`sanitizer-chain-error.log` 保留修复前 Aeternity 越界报告。`build/` 不纳入版本控制，复制项目时需另行保留这些证据。
