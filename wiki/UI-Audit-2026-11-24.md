# 2026-11-24 · Board 7 bilingual UI audit

[中文](UI-Audit-2026-11-24-zh) · [Individual frames](UI-Gallery) · [Boards and display](Boards-and-Display)

This iteration updates and validates the 296 × 128 landscape UI for board 7, delivering 44 states as 88 separate PNGs. LVGL 9.5.0 renders the firmware's `WalletUi.cpp`, followed by the real `eink_pack_landscape()` controller conversion. The images use public host fixtures. **They do not establish complete wallet functionality, support for every chain, or secure-card signing.**

## Images and interaction

Use the [filterable HTML gallery](ui-gallery/index.html) or the [Markdown gallery](UI-Gallery), which places each English and Chinese PNG in its own cell. Native PNGs are 296 × 128, 1 bpp. Six overviews provide separate borders, spacing and bilingual captions: [1](ui-gallery/overview-1.png) · [2](ui-gallery/overview-2.png) · [3](ui-gallery/overview-3.png) · [4](ui-gallery/overview-4.png) · [5](ui-gallery/overview-5.png) · [6](ui-gallery/overview-6.png).

States cover home, language, controls, creation and recovery choices and availability notices, unavailable camera capture, asset pagination and empty state, asset details, receive addresses, transaction review and decisions, serial confirmation codes, refusal and error states, pairing, OTP, processing and long notices. Several states capture scrolling within one page; 44 states do not mean 44 separate features.

With the display on the left, application keys are OK, Previous, Next and Back. Switch designators SW1/SW2 and the power switch are excluded. Focus uses white text on black. Transaction and pairing pages initially focus the scrollable body. OK selects Reject first; approval requires selecting the other button and separately holding OK for 750 ms. Back rejects. Approval delivery waits for a committed display and each callback is delivered once.

`Language / 语言` on the home menu switches English and Simplified Chinese. The preference lasts until power-off and defaults to English after restart. Active reviews, pairing, OTP and pending decisions prevent switching. Addresses, amounts, fingerprints, memo, calldata, account names and token symbols retain their original content. Only ownership fields explicitly marked as firmware labels are translated; a host account named `EXTERNAL` retains that exact name.

## Findings addressed

| Finding | Change and verification |
| --- | --- |
| English menu content was 14 px high with a 15 px font line | Use 22 px menu buttons and check every button label against its content height. Home shows three complete rows. |
| A fixed buffer could truncate pairing fingerprints | Render the full wrapping fingerprint; cover a 220-character fixture and scrolling. |
| Pairing and serial-code reviews lacked keypad reading focus | Add body focus and scrolling, including access to the final confirmation and seal codes. |
| Repeated or premature approval callback delivery | Deliver once, wait for display commit, and exercise short press, long press, Back and repeated holds. |
| An invalid replacement review could leave an older page visible | Show refusal and revoke old authorization. Excess outputs, truncated formatted fields and entropy failure cannot authorize. |
| Unsupported glyphs, malformed UTF-8 or direction controls could obscure review text | Validate all sealed review strings before enabling authorization. Invalid pairing data is also refused. |
| Asset details and pagination were incomplete | Add scrollable details, wrapping names, page bounds and empty-state focus. Ryo/Zano fixtures follow the release signing gates. |
| Long notices crowded out content; QR failure retained an empty column | Put ordinary long notices in the scrollable body and hide the failed QR column while retaining the full address and path. |
| A display error retained OTP memory | Zero the code and clear display/authorization state. |
| The common signing-review helper silently capped excess outputs | Refuse the complete request instead of displaying a subset. |

## Reproduction

From the repository root, prepare the pinned font source and converter as described in `assets/fonts/README.md`, then run:

```powershell
python tools/generate_ui_font.py --check
powershell -ExecutionPolicy Bypass -File tests/host/ui_check.ps1
python -m pip install Pillow==12.3.0 zxing-cpp==2.3.0
python tests/host/ui/export_panel.py build/ui-test/panel-frames wiki/ui-gallery --markdown wiki/UI-Gallery.md
```

This run used `build/audit-ui` and `build/audit-ui-sanitized`; add `--compare build/audit-ui-sanitized/panel-frames` when exporting the Release frames. Windows clang-cl needs its resource directory's `lib/x86_64-unknown-windows-msvc` available for linking and DLL lookup. Add that directory to `PATH` before CTest. This run used the MSVC developer environment, Ninja Multi-Config and the ASan DLL from that directory.

Logs in `build/audit-logs/`: `ui-bilingual-release.log`, `ui-bilingual-sanitized.log`, `p4-ui-bilingual-build.log`, `ui-native-security.log`, `ui-native-signing.log`, `ui-production-policy.log`, and `ui-protocol-sdk.log`.

Documentation checks found the four older requirement screenshots missing from the current workspace. The capability review records their filenames and retains its existing item-by-item analysis. They were not replaced by rendered UI images. The publishing helper now copies the `ui-gallery` attachment directory; publishing was not executed.
